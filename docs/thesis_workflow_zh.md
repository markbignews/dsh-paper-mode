# 论文 AIGC 痕迹检测与改写：闭环流程方法论

> 配套仓库：cn-thesis-aigc-detector。本文说明"从拿到论文到交付定稿"的完整工作流，以及每一步的判定依据；语言特征与改写细则以 `references/aigc_signals_zh.md` 为准，本文不再重复细节。

## 0. 服务范围确认（硬性第一步：先问清用户要什么，再动论文）

用户提出论文处理需求（检测 AI 率/AIGC 率、降率改写、查重自查、引述核查、只导出等）后，**先主动问清本次要哪种服务范围**；**问清之前，不对论文运行任何检测/自查/改写**（读取输入、提取文本等必要准备除外）。上下文已明确范围（如用户一开口就点名"只测 AI 率""只要引述核查"等）则不重复问，直接按其范围执行。三选一：

1. **一条龙全流程**：按完整闭环走到底——论文初审（角色A）→ 需求参数确认 → 引述核查（角色B）→ 查重/检测轮次（角色C/D）→ 逐段修改意见 → 确认改写 → 复查循环 → 终审（角色E）→ 导出交付（默认选项）。
2. **只做某个环节**：用户点名只要其中一段，如"只测 AI 率 / AIGC 率""只查重自查""只引述核查""只改写降率""只导出 Word"——只执行该环节及其硬性前置（如改写必须先出计划并获确认、检测须先确认输入形态），**不自动扩展成完整闭环**，也不自动跑初审/终审。
3. **自定义**：按用户现场指定的范围与顺序执行（用户想要怎样就怎样）。

**红线不因范围缩小而豁免**：无论选哪种服务，估算类输出仍须带"估算非官方检测结果"声明；不得编造、不得改动事实/数字/术语/公式/图表与引用编号；环节内若有引述核查内容（如改写前的引述核查），疑点仍须明示。

## 0.1 三条底线（贯穿全程）

1. **估算 ≠ 官方结果**。一切按知网等 AIGC 检测的**语言特征**做的估算，都不是知网/维普/Turnitin 的官方判定；官方实测才是最终标准。每次汇报估算值都必须附带这句话。
2. **不得编造**。改写不得编造数据、实验、案例、引用；没有证据支撑时，宁可弱化语气、补充边界，也不伪造，更不得为"降率"保留或新增捏造内容。
3. **必须保留**。事实、数字、术语、公式、图表引用、引用编号、结论方向、学术语体（不口语化）在改写中一律不动。

## 0.2 论文初审（值不值得改；一条龙全流程内先于参数确认与任何检测）

拿到可判读的全文/章节文本后**最先执行**（单段局部精修请求按"片段自洽性"轻量执行；用户明确"直接改、不用审"可跳过并注明）——本步仅在服务范围确认为**一条龙全流程**或用户点名整篇/章节处理时自动执行；只做单环节（如只检测、只导出）时不自动跑本初审。

- **执行方式**：多 agent 宿主由 **角色A · 论文初审子代理**（全新上下文、任务包自带初审模板）执行，主 agent 不自行判定、不预置结论；单 agent 宿主由主 agent 按同一模板自查并注明。
- **初审四维**：① 立意与选题（题目-内容一致、问题成立、有贡献点）；② 结构与论证（逻辑连贯、论证链完整、结论有支撑）；③ 前后一致性（术语/数据/观点矛盾，须给两处相抵原文）；④ 内容质量与完成度（信息密度、套话空泛、整段雷同或拼凑抄袭）。外加可改性评估：问题属"定点可修"还是"需重写"，降率约束下能否改到可用。
- **裁决**：照录呈现初审报告——❌ **不值得改**：说明硬理由并**退出本流程**（可建议先重写框架/与导师对齐/涉抄袭不得代改；用户坚持则注明风险继续）；⚠️：先解决作者侧硬问题再继续；✅：进入需求参数确认。

## 0.5 开始前：需求参数确认（每次先问；上下文已有不重复问）

任何论文处理开始前先核对四项参数，**会话上下文已明确给出的不重复问**，只问缺失项，并用一句话复述确认（同一篇论文连续处理不重复问，换新论文/新任务重新核对）。服务范围确认为**单环节**（如只检测、只导出、只引述核查）时，只确认该环节所需参数，问完即进入对应环节；范围=一条龙全流程时按下列四项问齐：

1. **目标优先级**：只降 AIGC 率 / 只降查重率 / 两者都做。两者都做时**默认走统一轮**：角色C 查重自查 + 角色D AIGC 检测**并出报告（只查不改）** → 合并成一份**统一修改意见** → 确认后**一次统一改写**（同段两类问题一次改到位）→ **新角色C 与新角色D 并行复查同一稿**，直到两项都达标——不再分"查重轮改完→AIGC 轮再改"两轮改写（省一半意见/确认/改写/复查轮次）；用户明确要求分先后两轮（默认先查重后 AIGC）时从其指定。
2. **学历级别**：本科 / 硕士 / 博士——用于给出查重合格线经验建议与行文分寸。
3. **论文级别（类型）**：本科毕业论文 / 硕士学位论文 / 博士学位论文 / 期刊论文（普刊或核心）/ 会议论文 / 课程论文等。
4. **目标比例**：AIGC 估算率 ≤？%（未指定默认 ≤10%）；若含查重：查重率 ≤？%（未指定按学历建议——本科 ≤30%、硕士 ≤20%、博士 ≤15%——以用户确认为准）。

查重相关的机制与降重策略另见 `references/duplicate_check_zh.md`（与 AI 率同构：本地只做风险估算，官方报告为准）。

**角色与轮次（多 agent 宿主）**：任何检测/自查都由**全新上下文**的独立子代理完成（角色任务书见 `references/subagent_prompts/`，先 read 再执行）——角色A 论文初审最先执行（判定值不值得改，❌ 即退出）；角色B 引述核查恒先行于指标轮次；两者都做时默认走**统一轮**：角色C 查重风险自查与角色D AIGC 检测**并出报告** → 统一修改意见 → 一次统一改写 → **新角色C 与新角色D 并行复查同一稿** → 两项都达标后，由 **角色E · 改后终审子代理**（全新上下文）对改后全文做交付前审核（合规/内容保真/论证/语体 + 残留风险），✅ 通过才导出交付，⚠️/❌ 定点返修后重开新角色E 再审；只做单项则只跑对应检测与复查；用户要求分轮时按"先查重轮再 AIGC 轮"执行；无子代理的宿主按对应版本 SKILL 的单 agent 降级与盲评路径执行，纪律不变。（以上 A–E 编排均针对**一条龙全流程**；服务范围=单环节时只跑所选环节。）

**统一命名与执行排序**：角色A 论文初审 → 角色B 引述核查 → 角色C 查重自查 ∥ 角色D AI 率检测（统一轮中并出报告）→ 统一改写 → 新角色C ∥ 新角色D 并行复查 → 角色E 改后终审（字母=默认执行序；用户要求分轮时先查重后 AIGC）。

## 0.6 控制条款（v2.7.0：上限 / 机检 / 回传 / 记账；v2.6.0 起 0 服务范围确认为硬性首步；v2.7.0 起默认统一轮）

- **迭代上限（硬性）**：每次"统一改写→并行复查"的定点迭代最多 **3 次**；第 3 次未达标即停在决策点（继续迭代——第 4 轮起需用户逐轮明示"继续" / 接受现状并记账 / 调整目标比例或处理顺序），未经用户明示不得自动进入第 4 轮。
- **终审返修上限（硬性）**：角色E 终审返修最多 **2 轮**；之后由用户决策（接受现状并记账 / 继续返修需明示 / 暂停并人工介入）。
- **保真机检（终审前必做）**：`python3 scripts/faith_check.py <原文> <改后> [--report …]` 输出数字、图表/公式/引用编号、拉丁术语的确定性差异清单，角色E 须逐条解释或修正；脚本只出证据（中文术语与语义保真仍由角色E 判定），数字/编号类差异不得跳过。
- **官方实测回传（正式节点）**：交付后用户回传官方报告/标红段 → 如实解读指标（总复制比/去除引用/去除本人/单篇最大/疑似 AI 段）→ 按标红类型重开对应轮（查重标红→角色C；AIGC 疑似→角色D）全新子代理复核 → 用户确认后定点改写（文件名版本续增并标注，如 `改写v4_回传精修.txt`）→ 新角色C/D 复查（≤3 次）→ 涉及全文再过角色E 与保真机检；精修完成前不宣称"过关"。
- **例外与跳过记账（硬性）**：跳过（初审/终审/参数某项）、坚持修改 ❌/⚠️ 结论、接受未达标现状、调整目标或顺序，一律记账——有文件系统写任务目录 `02_报告/决策与例外记录.md`，否则并入交付总结单列「例外与跳过」节；交付末尾固定输出清单，无则写"无"。

## 1. 整体闭环

```
⓪ 服务范围确认（一条龙全流程 / 只做某个环节 / 自定义；问清前不做任何检测）
→ 一条龙全流程：论文初审（角色A：值不值得改；❌ 即退出）
→ 需求参数确认（优先级/学历/论文级别/目标比例；单环节只问该环节所需）
→ ①引述核查（角色B） → ②自查/检测并出报告（查重角色C ∥ AIGC 角色D，只查不改）
→ ③统一修改意见（两份报告合并，与作者确认）
→ ④一次统一改写（同段两类问题一次改到位）
→ ⑤并行复查（新角色C ∥ 新角色D 重估同一稿） → 未达标回到 ③/④ 定点改最红的段
→ 两项都达标 → ⑥终审（角色E：改后全文交付审核，⚠️/❌ 定点返修再审）
→ ⑦精确导出定稿 → 作者上官方平台实测 → 标红段落回传，进入二次精修
```

## 2. 阶段 ①：引述/引用可靠性核查（前置，先于任何检测）

顺序不可颠倒：引述没核清之前，不做 AI 率检测。

- 把全文的引述逐条编号：作者+年份、文献题名、引文、数据/图表来源、机构/人名、方法出处、URL/编号。
- **逐条独立核验**：建议每条引述由一个不带上下文先验的独立评估者查证（可用 `web_search`/`web_fetch`），要点：来源是否真实存在、内容是否支撑所引主张、数据是否有出处。评估者不得预置"原文大概率没问题"的倾向。
- 汇总三条判定：✅ 可查证且真实支撑结论；⚠️ 信息对不上或查不到但无法排除；❌ 疑似捏造。
- ⚠️/❌ 必须向作者**明示**——这是独立于 AI 率的问题，不能靠改写掩盖。处理：有可靠同义来源则替换为真实来源；否则删除该引述、弱化论断或补边界。**不得编造"替身来源"。**

## 3. 阶段 ②：自查/检测（AI 率检测估算 + 查重风险自查，默认并出报告）

- 统一轮默认**两份报告并出**：AIGC 检测（本阶段）+ 查重风险自查（角色C，按 `references/duplicate_check_zh.md` 逐块给高风险段落清单，注明"非官方查重结果"）；只做单项则只出对应报告。
- **独立评估原则**：每一次估算——首次检测与改写后的复查重测——都由一个**不携带前序对话/改写记录**的独立评估者执行，避免"改写着自测"的乐观偏差与前序判定锚定。主流程只提供方法（信号库路径、扫描脚本、判定标准），不提供此前的判定结论；复查轮可附上"上一版报告供对照"，但评估者须先独立判定。
- 机械步骤（AIGC 检测）：
  1. 把全文落盘为 `.txt`（或直接用 `.docx`）；
  2. 跑确定性扫描 `python3 scripts/ai_signal.py <文件>`（自动按 150–450 字分块，输出句长节奏/连接词/套话/缓和语/引用数据等信号）；
  3. 评估者结合 `references/aigc_signals_zh.md` 逐块判读：**风险等级**（高=AI 特征强 / 中=疑似 / 低=更像人写）、命中信号编号、缓和信号、修改优先级。
- 估算方法：高=1.0、中=0.5 加权 × 字符占比 → 估算总 AI 率（约 X%）+ 置信度，并声明估算非官方。
- 输出报告：块号｜风险等级｜命中特征｜缓和信号｜估算区间，加"优先级最高的待改段落清单"。
- 提示：摘要/Abstract、纯文献罗列段、方法学固定表述（如"采用双向固定效应模型"）结构化程度高，优先提示但**不作为主要改写目标**。

## 4. 阶段 ③：统一修改意见（先给方案，作者确认后才动手）

1. 确认目标比例（未给时默认 ≤10%；目标 <10% 需如实告知：约 10% 是中文学术语体实用下限，再低会明显损伤学术性）。
2. 把**查重自查报告**（角色C，若目标含查重）与 **AI 率检测报告**（角色D，若目标含 AIGC）合并成一份清单，**不改写原文**：段落位置 → 原句摘录 → 命中的问题（查重：风险类型/可疑句；AI：信号编号；同段两类都命中并成一条）→ 具体改法（≤3 条）→ 不改的部分。
3. 作者确认范围（只改高危段还是全文过一遍）后，进入**一次统一改写**（同段两类问题一次改到位）。计划优先，绝不未经确认一次性大改全文。

## 5. 阶段 ④：改写规则（摘要，细则见信号库四、五节）

**做**（核心：只动句法，少动词汇；变化节奏与密度；用真实证据做缓和信号）：

- 打破工整排比/三段式：`首先…其次…最后`→自然过渡；三元并列改为不对称（重要的多说，次要的简说）。
- 变化句长节奏：混入 10–18 字短句与 40+ 字带从句长句；拆 40+ 字长句于转折处。
- 术语不动，挪句法角色：避免术语总在主语位（"XX 是/具有"），移到宾语/状语/定语或用指代复指。
- 削减功能重叠连接词：同段同功能只留 1 个，其余删掉或用标点/句子逻辑承接。
- 删套话与段尾元话语收束：值得注意的是/总的来说/综上所述/具有重要意义/不可忽视 等。
- 去模糊归因：无出处的"专家认为/研究表明"改为本文判断或给具体来源。
- 注入作者视角：承认局限、表达意外、留判断（"笔者认为…"）。
- 泛化结论改可检验推论："具有重要意义"→可验证的命题。
- 写新内容按"预防性写作 8 条"（具体动词、长短句交替、不编号自然过渡、直接说事、去连接词、段长不均匀、用"而/则"、穿插 ≤10 字短句）——从源头避免，比事后修高效 5–10 倍。
- 有真实引用/数据/图表的段落，把证据放在显眼论证位置——比任何措辞技巧都有效。

**禁**：

- 换同义词（"显著"→"明显"）——检测器抓句法节奏，不抓词汇替换，无效。
- 全面口语化/网络化（会从"AI 腔"倒向"博客腔"）、删光"较为/往往/可能"等留余地学术语、给术语加引号制造距离感、为降率篡改数据或结论、一次大改全部段落导致信息密度全线下降。

## 6. 阶段 ⑤：并行复查与迭代（直到两项都达标）

1. **硬约束自检表**（每段+全文，细则见信号库第六节）：AI 高频词每段 ≤2；段末总结套句全文 ≤1；整齐三元/四元并列每段 ≤1；"基于/依据XX理论"起笔段落 ≤20%；泛化结尾全文 0 处；模糊归因全文 0 处；正文加粗 ≤5 处。
2. **噪声预算**：每千字保留 2–3 处轻微 AI 特征作为自然噪声（如两项并列、程度较轻的过渡词全文 ≤1 处），**不要过度清洁**——全面均质化会触发另一类标记。同时复核：事实数字未变？术语未动？无新增编造？仍是学术语体？
3. 对改写后文本重跑 `ai_signal.py`，与改写前输出对比。
4. **再开独立评估者并行复查同一稿**（同阶段②，不带改写记录）：目标含 AIGC → 新角色D 重估 AI 率；含查重 → 新角色C 重估查重风险。新旧报告并排对比，如实汇报两项指标的新值与差距。
5. 未达标则只定点改当前最红的段落，循环 ③–⑤。两项都达标后总结：改动段数/总字符、命中特征消除情况、估算前后对比、自查结论。

## 7. 阶段 ⑥：交付

- 落盘默认：各阶段长报告进 `02_报告/`、改写稿进 `03_改写稿/`，聊天只给"结论摘要 + 最高优先级项（≤5 条）+ 文件路径"；逐段对照以代表段示例（≤3 处）呈现，全文对照见文件。仅极短结论可只聊不落盘。
- **精确导出 .docx**：用 `scripts/docx_write.py <定稿.txt> <输出.docx>` 把定稿原样装回 Word（支持 `#` 标题与 `**加粗**`），**不要**让任何工具"按主题重写"定稿内容。导出后用 `office_extract.py` 回读可复核逐字一致。
- 交付时提醒：**务必上知网等官方平台实测**；把官方仍标红的段落回传，进入二次精修（这是把 AI 率真正压下去的最有效方式）。

## 8. 误用与边界（务必让使用者知晓）

- 本方法解决的是"AI 辅助写作后语言风格趋同"的**表达层问题**；它不解决、也不应被用于掩盖：抄袭、代写、伪造数据、无出处引用等实质学术不端。
- 不同机构对生成式 AI 的披露要求不同，作者有义务按所在机构/期刊规定如实披露 AI 辅助情况。
- 检测阈值与算法随厂商更新而变化，任何估算都有时效；官方检测结果为准。
